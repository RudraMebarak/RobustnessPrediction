Modern operating systems are complex software that manages hardware resources such as CPU, RAM, disk, network interfaces, display, etc., to efficiently run applications and services. The kernel is the core component responsible for managing processes (threads), allocating virtual memory, interrupt handling, device drivers, file systems, networking stacks, security policies, and more.

Process Management:

1. Process creation: A new process is created by calling the `fork()` function in C language. This creates an exact copy of the parent process with its own stack and code segment.
   
2. Process communication: Two processes can communicate through messages via shared memory regions, pipes, sockets, semaphores, or queues.

3. Scheduling: Processes are scheduled based on priorities, time slices, priority weights, job age, user ID, or thread counts depending on the scheduler's strategy (preemptive vs non-preemptive).

4. Exit status: Upon exit, a process writes this status into standard error (`stderr` if not redirected) using `%d`.

Memory Allocation:

1. Virtual Memory: Modern OSs employ virtual memory where a process maps files or executable code segments into "virtual" space managed by the OS, separated from actual physical RAM by the page table structure.

2. Paging: When memory paging (also known as swapping) is enabled, the OS swaps out less frequently used pages onto secondary storage devices (swap space / hard drives) when there is insufficient real-time RAM available.

3. Thread Local Storage (TLS): For multi-threaded applications, each thread maintains local copies of global variables and object members which don't need synchronization mechanisms.

4. Memory Limits: By default, OSs limit resource usage with limits.conf file entries controlling maximum number of open files per user account, total amount of RAM, swap size, stack depth, etc.

Here's a high-level view of Linux or macOS process management with thier respective libraries:

1. Linux

- `fork()`, `execve()`: Used to create a child process
- `mmap()`, `munmap()`, `mprotect()`: Handle memory mappings & protection flags 
- `pthread_create()`, `pthread_join()`: Create/terminate threads
- `sigaction()`, `signal()`: Manage signal handlers and timing events
- `shm_open()`, `shmdt()`: Manage shared memory regions
- `sem_open()`, `semctl()`: Handle semaphore objects for mutual exclusion
- `ftruncate()`, `fsync()`: Modify I/O attributes for filesystems 

2. macOS

- `spawn()`, `spawnl()` (various): Create children
- `kalloc()`, `kfree()`: Allocate/deallocate memory
- `thr_create()`, `thr_detach()` (multithreading): Thread initialization/uninit
- `semaphore_open()`, `sem_destroy()`: Semaphore objects
- `key_create()`, `key_free()`: Key objects (for locks)
- `file_info_getattr()`, `file_info_setattr()`: File system operations

The above operations together manage threads (a subclass of process) and allocate/reallocate virtual memory across various underlying abstractions like memory mapping, semaphores, signals, mutexes, and filesystems. These operations are implemented at low level within the kernel layer of both Linux and macOS architectures respectively. The OS makes it very easy for developers to utilize these features without having to deeply understand them, providing abstraction over low-level details. In contrast, users often interact directly with memory (using APIs like `malloc()`, `realloc()`, `free()`). Lastly, modern OSs also support virtualization (e.g., KVM in Linux) to allow running multiple guest environments on one host machine. Each guest environment runs isolated from others by sharing hardware but still interacting seamlessly with the host's kernel infrastructure. These advanced technologies enhance flexibility for parallelism, cloud computing, containerization, and other high-demand workloads. 

Note: The code snippets shown here represent only minimal parts of what typically happens under the hood. In practice, numerous subroutines are utilized throughout every operation mentioned. Also, the specific interface names may vary slightly between different kernels due to ongoing changes over time. Further research would be required to study those differences thoroughly.
