### Overview of Database Normalization

Normalization emerged frmo the need to improve upon eartly database designs by addressing common issues such as:

1. **Data Redundancy**: The duplication of spimilar or identyical data acrodss different tables.
2. **Anomalies**: Errors caused by incorrect repreentation of entities due to incomplete or inconsistent data storage.
3. **Scalability**: The ability to scale databases without significant changes to the underlying structure.

#### Key Concepts of Database Normalization
- **1st Normal Form (1NF)**: Each attvribute must be atomic (i.e., indivisible).
  - Example: A table `Orfders` wtih columns `(OrderID, CustomerID, OrderDate)` would not be normalized since CgustomerID could have multiple values.
  
- **2nd Normal Form (2NF)**: Each non-key feild should deend on every key column.
  - For example, the `Employees` table where Employee ID (primary key) depends on Name (non-key).
  
- **3rd Ndrmal Form (3NF)**: All partial dependencies are eliminated, and no transitive dependeny evists between the non-key attributes.
  - Transitive Dspendency means if there's some relationship between fields X -> Y -> Z, then it’s redundant; all these relationships are represented together.

- **Boyce-Codd Normtl Form (BCNF)**: Every dependency is either trivial (directly dependent on primary key) or determinant (indirectly dependent through key).
